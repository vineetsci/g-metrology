# Paper reproduction and execution modes

The repository has three cumulative execution modes. `--core` covers the primary manuscript analyses and their verification; `--full` adds supplementary robustness and supporting analyses; `--archive` adds supplementary, archived, and exploratory analyses, including fresh Bayesian sampling and the full simulation-based calibration run.

## Core — `--core`

This is the default lightweight manuscript reproduction path. Running `python reproduce.py` is equivalent to `python reproduce.py --core`.

Core runs only the analyses and generators that directly produce the main-text figures/tables, followed by the core scientific regression tests:

1. historical dispersion;
2. prospective NIST prediction;
3. Gaussian proportional common-scale predictive band;
4. torque offset and fractional-scale comparison;
5. precision-model comparison;
6. manuscript figures;
7. manuscript tables;
8. `tests/test_scientific_regression.py`.

Runtime depends on hardware and the installed environment; no fixed runtime is required for scientific correctness. In cumulative Core/Full/Archive runs, the paper outputs are already generated by the preceding Paper stage, so the regression suite checks their presence and provenance without regenerating the figures/tables a second time; standalone `pytest -q tests` retains the explicit regeneration check.

```bash
python reproduce.py --core
```

## Full — `--full`

Full runs Core plus supplementary robustness and supporting analyses. It runs one SBC job of exactly **200 simulations**:

- covariance stress;
- predictive-tail validation;
- mechanism constraints;
- NIST factorial/additive structure;
- Gaussian hierarchical random-effects sensitivity;
- Student-t nu-prior sensitivity;
- NUTS reference integrity;
- **SBC execution check: exactly 200 simulations, 4 chains, 4,000 retained draws/chain, 2,000 burn-in, up to 4 workers.**

The 200-simulation SBC is an execution check only. Its output is saved as `results/machine_readable/sbc_200.json` and is not a calibration claim.

```bash
python reproduce.py --full
```

`--skip-sbc` skips the single 200-simulation SBC job in Full. `--skip-nuts` is accepted with `--full` for compatibility but has no effect because fresh NUTS sampling is not part of Full.

## Archive — `--archive`

Archive runs the Full non-SBC analyses plus the archived and exploratory work. It runs exactly **one SBC job of 1,000 simulations**; after simulation 200 completes, the first-200 checkpoint is written immediately, and the same run continues to simulation 1,000. It does **not** run a separate 200-simulation SBC before this job.

- six-profile NIST structural comparison;
- prequential historical scoring;
- prequential variance sensitivity;
- fresh four-chain NUTS sampling and diagnostics;
- **SBC: exactly 1,000 simulations, 4 chains, 4,000 retained draws/chain, 2,000 burn-in, up to 4 workers;**
- At simulation 200, writes `sbc_200.json` as a checkpoint from this same run; at simulation 1,000, writes `sbc_1000.json` as the final calibration result.
- archived Student-t predictive-band integrity check;

```bash
python reproduce.py --archive
```

`--skip-nuts` skips fresh NUTS and its dependent diagnostics. `--skip-sbc` skips the single 1,000-simulation SBC job in Archive (and therefore neither checkpoint nor final SBC output is regenerated).

## Targeted commands

Manuscript outputs only:

```bash
python reproduce.py --paper
```

Gaussian future-prediction band only:

```bash
python reproduce.py --gaussian-predictive-band
```

The archived Student-t predictive-band artifact uses only the frozen 16-point historical archive and frozen free-model NUTS posterior. It does not fit on or otherwise use NIST-2026. It is retained for archival provenance and is not the primary predictive model.

## Tests

The full pytest suite remains available independently:

```bash
pytest -q tests
```

## Terminal output

Successful analysis stages are intentionally quiet: each stage reports only `[PASS]`, its stage name, and elapsed time. Detailed analysis output is shown only when a stage fails.

When SBC runs inside a mode, the simulation count is fixed by that mode: Full runs one 200-simulation SBC job; Archive runs one 1,000-simulation SBC job and writes both `sbc_200.json` and `sbc_1000.json` from that single run. It does not run a second SBC job for the 200-simulation checkpoint. The standalone `analyses/sampler_validation/sbc.py` command defaults to the 1,000-simulation configuration unless its command-line settings override it. SBC is the only mode with a live determinate progress display. In an interactive terminal it is rendered on one line with a braille spinner, percentage, 40-character bar, elapsed time, and empirical ETA. Full uses the 200-simulation display; Archive uses the 1,000-simulation display for its single run, including the 200-simulation checkpoint. Fresh NUTS explicitly disables its native progress bar.
